# Configuration

Spend Guard is configured from **Settings → Plugins → Spend Guard** in the
Paperclip UI. The form is auto-generated by the host from the plugin manifest's
`instanceConfigSchema`. Every field is optional.

| Field | Type | Default | Meaning |
|---|---|---|---|
| `perAgentUsd` | number ≥ 0 | _(none)_ | Alert when a single agent's attributed spend reaches this many US dollars. Omit for no per-agent ceiling. |
| `perIssueUsd` | number ≥ 0 | _(none)_ | Alert when a single issue/task's attributed spend reaches this many US dollars. |
| `perDayUsd` | number ≥ 0 | _(none)_ | Alert when total attributed spend for a UTC calendar day reaches this many US dollars. |
| `warnRatio` | number (0, 1] | `0.8` | Fraction of a ceiling at which an early **warn** fires (e.g. `0.8` = warn at 80%). The full **alert** always fires at 100%. |
| `pauseAgentOnCeiling` | boolean | `false` | Opt-in enforcement: when `true`, pause an agent once it reaches its per-agent ceiling. Default OFF (alert-only). |

## Semantics and validation

- **Omitting a ceiling means "track but never alert"** for that scope. Spend is
  still attributed and visible to the `spend_guard_status` tool; it just never
  triggers a threshold event.
- Non-positive ceilings are treated as "not configured".
- `warnRatio` is clamped into `(0, 1]`; out-of-range values fall back to `0.8`.
- The plugin's `validateConfig` ("Test Connection" in the settings UI) returns
  warnings when:
  - `pauseAgentOnCeiling` is on but no `perAgentUsd` ceiling is set (nothing to
    enforce), or
  - no ceilings are configured at all (tracking-only mode).

## Buckets and time

- Attribution buckets are **per agent**, **per issue**, and **per UTC day**.
- The day bucket key is `YYYY-MM-DD` in **UTC**. This is intentionally timezone
  independent in v0.1.0; a configurable timezone may be added later.
- Each day is its own bucket; "rolling" simply means old days stop being written
  to. There is no automatic purge of historical day buckets in v0.1.0.

## A note on dollar accuracy

See the README "Contract notes". In the current Paperclip build, dollar figures
are driven primarily by **budget-incident** events (the host's own observed
amounts), which makes attribution approximate and biased toward over-reporting.
Run **counts** and threshold behavior are exact. Precise per-run dollar
attribution activates automatically if/when the host begins emitting
`cost_event.created`.
